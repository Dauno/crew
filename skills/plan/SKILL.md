# Plan a change

Use this skill only while planning. Change nothing until the human approves.

## Verify and question

1. Read the request and verify relevant facts in the repository.
   Note assumptions that could affect scope or sequence.
2. Mark claims you cannot verify.
3. Question the request. Push back on work the need does not justify.
4. Identify repository contracts. A contract change needs approval from the
   coordinator and the human.

## Present decisions

Present numbered decisions, each with a recommendation. The human answers by
number. If a decision remains unanswered, take the recommendation and say so
explicitly.

Record each human decision with its exact quote through the memory skill.
Quote each decision exactly, in the human's language. If you work as a node,
send the exact quote and intended scope to the parent.

## Plan work with nodes

When implementation uses worker nodes, list each planned node, CLI, model and
effort. Wait for approval before spawning any node.

Write the brief under `$CREW_RUNS/<task>/`. Include the goal, decisions and
quotes, approved contract changes, rules and report paths.

When no nodes are needed, state the implementation scope and verification
plan without creating unnecessary machinery.
